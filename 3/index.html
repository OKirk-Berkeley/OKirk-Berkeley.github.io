In part A, I explore what kind of things are possible using a trained image denoising model. I don't do any of my own model training until part B. Many of the techniques in this part rely on often critiqued (and rightly so) aspect of AI - its ability to hallucinate. If we pass a model that has been trained to denoise an image an input that is pure noise, it will "hallucinate" that it has been passed a natural image with noise added, and actually recover this "hallucinated" image! This part of the part of the project explores how we can harness this to create meaningful images.

Section 1: Visualizing Training and Sampling

1.1 Constructing Noisy Training Inputs

The building block for this style of image generation is noisy images. Models capable of estimating original images from noisy recreations are trained on natural images and their corresponding noisy counterparts. Generating such images is simple. At any given noise level t, every pixel in our noisy image (xt) is a weighted average of the corresponding pixel value in our input image and pure Gaussian noise (ε). The equation is given by xt = t * x1 + (1 - t) * ε. Here are examples of a clean image (on the left) and its noisy counterparts at t values of 0.25, 0.5, and 0.75.

1.2 Classical Denoising

One way to try to correct the noise is by making the value of each output pixel an average of its neighbors. Since the noise has a mean value of 0, we expect it to cancel out when summed across multiple values, leaving just the original pixel values. This can be done using a Guassin blur on the noisy image (although for best results the noisy image should be divided by t first to reproduce an output image of the same amplitude as the input). However, the Gaussian blur also removes fine details from our image. The noisier the input, the more pixels have to be averaged to get a reliable output and the blurrier the output becomes. Results using this denoising method are shown below. Note how for noiser images a larger Gaussian blur kernel was needed, resulting in a blurrier output.

1.3 One-Step Denoising

A better approach is to train a model to denoise the images for us. The model predicts a path (called a "velocity") from our noisy image to its clean counterpart. The original image can be recovered using this formula x1 = xt + (1 - t) * v where v is the predicted velocity. Our velocity predictor takes 3 inputs: the noisy image, the value of t, and a text prompt describing the image we want it to produce a velocity towards. Below are the results of this denoising process at various noise levels, all using the text prompt "a high quality photo". Much better than the Gaussian blur, but even this tequnique produces images that don't look very real on high-noise inputs.

1.4 Visualizing Velocity

Since we have the original image, we can calculate what our velocity should be by subtracting the noise from the original image. The corresponding image update is this velocity scaled by (1 - t), which is the same as the original image minus the noisy image. This makes sense because it is the value we want to add to our noisy image to recover the original. This objectively correct update is compared to our predicted updated at a variety of noise levels below. Also included is a heat map showing where the predicted and correct updates differ.

At higher noise levels, the model struggles to accurately predict things like the texture of the bread or of the cheese. The true updates also contain exact imprints of the noise pattern, which our model doesn't know, so can't recreate.

1.5 Iterative Denoising with Euler Sampling

To improve on this even more, we can slowly denoise the image using tiny steps. Since our denoising model is less accurate at higher noise levels, we don't have to denoise all at once. Instead, we can predict the velocity at the given noise level and only move the image a little in that direction. Then, we can predict the velocity again and move a little in the direction of the new velocity. The result of this process is shown below where the image was denoised over 25 steps. The partially denoised image is shown from every 5th step with the corresponding t.

Below is a comparison of all the denoising method on the same noisy input (with t-value 0.5). The blurred image fails to eliminate all the noise while reducing image detail. The one-step denoiser is much better but still struggles to recrate the fine textures from the original image with only one chance to predict the velocity from a very noisy image. The Euler method is the best (although also the most computationally expensive), as it can refine its velocity predictions as the noise decreases.

1.6 Generating Images from Noise

This technique can be expanded to generate images. If instead of passing our Euler denoising method a noisy recreation of an image we pass it pure noise, it will still be capable of "denoising" our image. Now, instead of trying to recreate an altered input image, it is guided only by the textual prompt the denoiser is given. Section 2: Conditional Generation and Guidance

2.1 Classifier-Free Guidance (CFG)

With no original image, it makes sense to strengthen the impact of our textual prompt. This can be done through classifier-free guidance (CFG). We can isolate the aspects of our velocity that relate to our text prompt by subtracting a velocity generated without a text prompt from our calculated velocity. We can then add these isolated aspects back into our final velocity to strengthen them. The final equation is vCFG = vtext + w * (vtext - vno text) where w is how strongly we add to increase these elements. Here are results using w = 7 and prompt "a high quality photo".

Section 3: Creative Applications

3.1 Image-to-Image Editing

We can use this to "edit" images! By adding some noise to our images and using our new denoising strategy with a much higher emphasis on the text prompt, we can get our model to output images that resemble the input broadly but are mostly generated by the model. This is different from part 1 because the model is not trying to recreate the original image, it is just trying to create an image that follows the text prompt. If it happens to be given an image with a clear structure, it will follow it, but the goal is just any image fitting the prompt. This is what that process looks like using prompt "a high quality photo", w = 7, and a variety of starting images and noise levels. The noisier an input is, the less its output will resemble the original.

3.3 Visual Anagrams

An even more creative application of this process is creating visual anagrams! Again generating images from pure noise (no input image) we can generate velocities for multiple textual prompts. To create images that depict different things at different rotations, we can generate one velocity with one prompt then another from the upside down version of the image with a different prompt. We can then flip that velocity upside down again so it aligns with a right side up version of the image. If we apply an update based off the averge of these velocities, an image that fits the first prompt when right side up but the second when upsdie down will emerge! While at first each seperate velocity may be pointing the final result towards completley noncomplementary images, as an image begins to gradually emerge the velocities will be basing the final off the current, shared image. 3.4 Hybrid Images

Another way to combine velocities is via hybrid images. Here, two velocities are generated from the same orientation of the image (with different prompts). To combine them, we sum the high frequencies (fine details) of one with the low frequencies (general shapes and colors) of the other. This produces a final image that matches the high-frequency prompt from up-close when the details are easy to see and matches the low-frequency from afar when only those details are visible.
