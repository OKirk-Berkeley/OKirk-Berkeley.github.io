In part A, I explore what kind of things are possible using a trained image denoising model. I don't do any of my own model training until part B. Many of the techniques in this part rely on an often-critiqued (and rightly so) aspect of AI — its ability to hallucinate. If we pass a model that has been trained to denoise an image an input that is pure noise, it will "hallucinate" that it has been passed a natural image with noise added, and actually recover this "hallucinated" image! This part of the project explores how we can harness this to create meaningful images.

Section 1: Visualizing Training and Sampling

1.1 Constructing Noisy Training Inputs

The building block for this style of image generation is noisy images. Models capable of estimating original images from noisy recreations are trained on natural images and their corresponding noisy counterparts. Generating such images is simple. At any given noise level t, every pixel in our noisy image (xt) is a weighted average of the corresponding pixel value in our input image and pure Gaussian noise (ε). The equation is given by xt = t * x1 + (1 - t) * ε. Here are examples of a clean image (on the left) and its noisy counterparts at t values of 0.25, 0.5, and 0.75.

1.2 Classical Denoising

One way to try to correct the noise is by making the value of each output pixel an average of its neighbors. Since the noise has a mean value of 0, we expect it to cancel out when summed across multiple values, leaving just the original pixel values. This can be done using a Gaussian blur on the noisy image (although for best results the noisy image should be divided by t first to reproduce an output image of the same amplitude as the input). However, the Gaussian blur also removes fine details from our image. The noisier the input, the more pixels have to be averaged to get a reliable output and the blurrier the output becomes. Results using this denoising method are shown below. Note how for noisier images a larger Gaussian blur kernel was needed, resulting in a blurrier output.

1.3 One-Step Denoising

A better approach is to train a model to denoise the images for us. The model predicts a path (called a "velocity") from our noisy image to its clean counterpart. The original image can be recovered using this formula x1 = xt + (1 - t) * v where v is the predicted velocity. Our velocity predictor takes 3 inputs: the noisy image, the value of t, and a text prompt describing the image we want it to produce a velocity towards. Below are the results of this denoising process at various noise levels, all using the text prompt "a high quality photo". Much better than the Gaussian blur, but even this technique produces images that don't look very real on high-noise inputs.

1.4 Visualizing Velocity

Since we have the original image, we can calculate what our velocity should be by subtracting the noise from the original image. The corresponding image update is this velocity scaled by (1 - t), which is the same as the original image minus the noisy image. This makes sense because it is the value we want to add to our noisy image to recover the original. This objectively correct update is compared to our predicted update at a variety of noise levels below. Also included is a heatmap showing where the predicted and correct updates differ.

At higher noise levels, the model struggles to accurately predict things like the texture of the bread or of the cheese. The true updates also contain exact imprints of the noise pattern, which our model doesn't know, so it can't recreate them.

1.5 Iterative Denoising with Euler Sampling

To improve on this even more, we can slowly denoise the image using tiny steps. Since our denoising model is less accurate at higher noise levels, we don't have to denoise all at once. Instead, we can predict the velocity at the given noise level and only move the image a little in that direction. Then, we can predict the velocity again and move a little in the direction of the new velocity. The result of this process is shown below, where the image was denoised over 25 steps. The partially denoised image is shown at every 5th step, with the corresponding t.

Below is a comparison of all the denoising methods on the same noisy input (with a t-value of 0.5). The blurred image fails to eliminate all the noise while reducing image detail. The one-step denoiser is much better but still struggles to recreate the fine textures from the original image with only one chance to predict the velocity from a very noisy image. The Euler method is the best (although also the most computationally expensive), as it can refine its velocity predictions as the noise decreases.

1.6 Generating Images from Noise

This technique can be expanded to generate images. If instead of passing our Euler denoising method a noisy recreation of an image, we pass it pure noise, it will still be capable of "denoising" our image. Now, instead of trying to recreate an altered input image, it is guided only by the textual prompt the denoiser is given. Section 2: Conditional Generation and Guidance

2.1 Classifier-Free Guidance (CFG)

With no original image, it makes sense to strengthen the impact of our textual prompt. This can be done through classifier-free guidance (CFG). We can isolate the aspects of our velocity that relate to our text prompt by subtracting a velocity generated without a text prompt from our calculated velocity. We can then add these isolated aspects back into our final velocity to strengthen them. The final equation is vCFG = vtext + w * (vtext - vno text) where w is how strongly we increase these elements. Here are results using w = 7 and the prompt "a high quality photo".

Section 3: Creative Applications

3.1 Image-to-Image Editing

We can use this to "edit" images! By adding some noise to our images and using our new denoising strategy with a much higher emphasis on the text prompt, we can get our model to output images that resemble the input broadly but are mostly generated by the model. This is different from part 1 because the model is not trying to recreate the original image. It is just trying to create an image that follows the text prompt. If it happens to be given an image with a clear structure, it will follow it, but the goal is just any image fitting the prompt. This is what that process looks like using the prompt "a high quality photo", w = 7, and a variety of starting images and noise levels. The noisier an input is, the less its output will resemble the original.

3.3 Visual Anagrams

An even more creative application of this process is creating visual anagrams! Again, generating images from pure noise (no input image), we can generate velocities for multiple textual prompts. To create images that depict different things at different rotations, we can generate one velocity with one prompt, then another from the upside-down version of the image with a different prompt. We can then flip that velocity upside down again so it aligns with a right-side-up version of the image. If we apply an update based on the average of these velocities, an image that fits the first prompt when right side up, but the second when upside down, will emerge! While at first each separate velocity may be pointing the final result toward completely non-complementary images, as an image begins to gradually emerge, the velocities will be basing the final result on the current, shared image. 3.4 Hybrid Images

Another way to combine velocities is via hybrid images. Here, two velocities are generated from the same orientation of the image (with different prompts). To combine them, we sum the high frequencies (fine details) of one with the low frequencies (general shapes and colors) of the other. This produces a final image that matches the high-frequency prompt up close, when the details are easy to see, and matches the low-frequency prompt from afar, when only those general shapes and colors are visible.

Part B: Flow Matching from Scratch

Part A was done using a pre-trained model to help with the denoising. In part B, I train a model myself using a 28x28 pixel handwritten digit image dataset.

Part 1: Training a Single-Step Denoising UNet

1.1–1.2.1 Implementing and Training a Denoiser

To train such a model, noisy inputs are needed. As in part A, these can be generated by adding Gaussian noise to our input image (although in part A we took a weighted average). Noisy image z is created by: z = x + σε where x is the original image, σ is the noise level, and ε is the noise. For now, we train the model on only σ = 0.5.

We train a U-Net model on these noisy images using Mean-Squared Error loss. U-Net models process the whole image, then smaller and smaller representations of it to isolate the most important features. They then scale these versions back up and combine them with the processed versions at each size in order to maintain the details present at each scale. The training loss over time is plotted below and samples of the model's denoising are shown at various points during the model's training.

Notice how after more training the model has learned the necessary weights to make the denoising much more precise.

1.2.2 Out-of-Distribution Testing

Since our model trained only on noisy images with σ = 0.5, it is ill-prepared to denoise images with different noise levels. Let's take a look at what the results look like for attempts at denoising images at various noise levels.

1.2.3 Denoising Pure Noise

Let's try one of our strategies from part A: inputting pure noise. Since this is only a one-step denoiser, it can't adjust its predictions as the image becomes less noisy. As a result, with only pure noise as a starting image the denoiser attempts to force the image back to the image that will reduce the mean squared error against all the training images. This ends up being the "average image" of our training set. This isn't a problem with model sophistication. We're using a model that isn't being trained to output new images, no matter how well it trains! This is why the results don't look any better after more training.

Part 2: Training a Flow Matching Model

2.1–2.2 Time-Conditioned UNet

To fix this, we need to return to another strategy from part A: denoising gradually using small steps. For this to work, we first need a denoiser capable of working on images of any noise level (not just 0.5). We can create such a model by adding input channels for the t variable to our processed image as we scale it up. If we make sure to randomize what noise level we use during training and include this in our model, the training process ends up being much the same.

2.3 Sampling from the Time-Conditioned UNet

We can now use our model to generate images from pure noise. By denoising little by little, and adjusting our predictions based on the current level of noise, our model can take a partially denoised image and guide it towards the individual digits it resembles. However, it is still influenced by every image, even if the images of other digits aren't relevant once it is clear which digit is being generated. This is why the results are so messy.

2.4–2.5 Class-Conditioned UNet

To solve this problem, we can condition our model not only on t but also on the digit we want to generate! This is done through a process very similar to conditioning on t, in which we allow the digit to influence the output at each level as we bring our image size back up. When training this model, we not only provide the noise level t but also the digit of the original image. In order to allow for meaningful images even when no digit is provided, in 10% of training examples we do not provide a digit.

2.6 Sampling from the Class-Conditioned UNet

In order to sample images, we revisit classifier-free guidance (CFG) from part A. The idea is the same, but this time we are using a digit instead of a text prompt. Another difference is that we add the isolated context velocity to an unconditional prediction as opposed to a conditional one like we did before. The velocity for each Euler step (tiny bit of denoising) is then u = uno digit + γ(udigit - uno digit). This makes our model more accurate and allows us to control the outputted digit at the same time! Four results for each digit are shown at various points in the training process below.

Throughout the training, we have decreased the learning rate of our model exponentially after each epoch of training in order to allow it to converge more easily. However, this is not necessary. I have recreated the same model using a constant learning rate for the entire training process. In the original training, the learning rate was multiplied by (0.1(1.0 / 10)) after each of 10 epochs. To try to produce similar results with a constant learning rate, I used the value the dynamic learning rate had halfway through the epochs. This was the initial learning rate, 0.01, times (0.1(1.0 / 10)) to the fifth power.
